## Catatan Khusus: DOKU Payment Gateway

### Yang Sudah Baik ✅
- **Payment token generation** didelegasikan ke Supabase Edge Function (`generate-payment`), artinya `DOKU_SECRET_KEY` tidak terekspos ke Next.js client bundle.
- **Status pembayaran** dicek via Supabase Edge Function (`check-payment-status`), bukan mengandalkan client-side redirect.
- **Checkout flow** di [checkout/page.tsx](file:///d:/Aulia%20Project/benangbaju/src/app/(customer)/checkout/page.tsx) sudah menangani idempotency dengan `checkout_locks` table.
- **Shipping cost** divalidasi ulang server-side sebelum order dibuat.

### Yang Perlu Diperhatikan ⚠️
- **Signature verification, idempotency handling, dan amount cross-checking pada webhook/notification** tidak bisa diaudit dari codebase ini karena logikanya ada di **Supabase Edge Functions** (`generate-payment`, `check-payment-status`) yang kodenya tidak ada di repo ini. **Ini adalah area high-risk yang harus diaudit secara terpisah.** Pastikan:
  - Signature DOKU diverifikasi dengan constant-time comparison di Edge Function.
  - Notifikasi idempoten (proses yang sama tidak dijalankan dua kali).
  - Amount dan invoice_number di notifikasi dicross-check ke database sebelum marking order sebagai paid.
  - Secret key diambil dari env var, bukan hardcoded.

## Hal yang Bukan Bug

Untuk kejelasan, berikut hal yang saya periksa dan **bukan** bug:
- `proxy.ts` digunakan menggantikan `middleware.ts` — ini konvensi Next.js 16, bukan masalah.
- `params` dan `searchParams` di-`await` di semua Server Component page — ini sudah benar untuk Next.js 16.
- `cookies()` di `server.ts` sudah di-`await` — benar.
- `cacheComponents: true` di `next.config.ts` mengaktifkan cache components — `use cache` di `produk/page.tsx` sudah digunakan dengan benar.
- `DOKU_SECRET_KEY` tidak ditemukan hardcoded di codebase — hanya ada di `.env.example` sebagai placeholder.
